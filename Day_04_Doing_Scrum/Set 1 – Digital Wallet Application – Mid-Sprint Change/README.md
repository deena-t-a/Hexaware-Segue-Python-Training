# Day 4 – Sprint Simulation Workshop (Set 1)
## Project: Digital Wallet Application – Mid-Sprint Change & Execution

### Overview
This repository and accompanying documentation simulate an active 10-day Sprint for a fintech development team working on a **Digital Wallet Application**. It captures end-to-end Scrum execution, including velocity-based capacity planning, daily stand-ups, impedance logging, disciplined mid-sprint scope change handling, burndown trend interpretation, sprint retrospectives, and the mapping of the Definition of Done (DoD) to an automated CI/CD build pipeline.

### Summary of Workshop Tasks Completed

1. **Sprint Planning & Capacity:** Computed the team's average velocity (23 Story Points) over the last 3 sprints, selected matching backlog items, and established a measurable Sprint Goal.
2. **Task Breakdown:** Broke down three core user stories (`DW-01`, `DW-02`, `DW-03`) into granular engineering sub-tasks with hour estimates.
3. **Daily Execution & Impediments:** Simulated Day 3 daily stand-up updates for three developers and maintained a structured impediment log detailing rapid resolutions for SSL certificate expiration and firewall blocks.
4. **Mid-Sprint Change Handling:** Managed an urgent business request on Day 4 to add a Refund-to-Wallet feature (`DW-06`, 5 pts) by negotiating a disciplined scope swap with the Product Owner (removing 5 points of unstarted stories to protect team capacity).
5. **Burndown Analysis:** Constructed and interpreted a 10-day sprint burndown chart tracking ideal vs. actual remaining story points.
6. **Retrospective & CI/CD Mapping:** Formulated actionable retrospective improvements with assigned owners and mapped each stage of the Definition of Done (DoD) directly to automated CI/CD pipeline gates (Build, Test, Review, Deploy).
